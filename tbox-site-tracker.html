🏗️How the site is builtconventions every change must follow — a fix is not done if it breaks these
  1. Static HTML/CSS/JS only. No build step, no framework. Pages are plain .html files served directly. All CSS lives in inline <style> blocks per page (global variables in /css/styles.css). No external runtime dependencies.
  2. Nav and footer are injected, not duplicated. /js/components.js (loaded with defer) fetches /components/nav.html and /components/footer.html and injects them into #nav-placeholder and #footer-placeholder. Never hardcode nav or footer in individual pages — edit only the component files.
  3. CSS custom properties are the color system. All colors come from var(--red), var(--text), var(--text-muted), var(--bg-alt), var(--border), var(--border-band), var(--mono) etc., defined in /css/styles.css. Hardcode hex only when a specific contrast override is intentional (e.g. #4A4845 for accessibility).
  4. Images go in /assets/, not inline. Blog images in /assets/images/blog/, product screenshots in /assets/[product]/. Optimize to WebP when possible. Blog cover images (downloaded from Unsplash, free commercial license) live at 800×500px.
  5. No external CDN requests on any page. Fonts are system stack. Icons are SVG inline or text. All JS is inline or loaded from /js/. Pages must load with zero external network requests.
  6. Every page needs proper <meta> coverage. description, og:title, og:description, og:image, canonical, and twitter:card. Blog posts additionally need og:type = article and article:published_time.
  7. Sitemap must be updated when pages are added. /sitemap.xml lists all URLs. Add new pages with their lastmod date; don't leave them out.
File structure reference

  • /assets/images/ — Shared images (logo, founder photo, favicons)

  • /sitemap.xml — All page URLs for search engines
